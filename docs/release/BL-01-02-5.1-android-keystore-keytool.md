# Task 5.1 — Generate Android upload keystore via `keytool`

**Story:** BL-01+02 · **Task:** 5.1 · **Deferred since:** 2026-05-16  
**Requirements:** AC-001, AC-006 (release signing with upload keystore)  
**Blocks:** Task **5.3** (Play fingerprint) · Android path of **5.4**

---

## Goal

Create a **Play upload keystore** (never commit it), wire it through `android/key.properties`, and confirm a release build signs with that key—not the debug key.

---

## Before you start

- [ ] JDK installed (`keytool -help` works in a terminal).
- [ ] Password manager ready to store keystore path, store password, key alias, and key password.
- [ ] Understand: **this upload key cannot be rotated casually**; loss requires Google Play support to reset.

---

## Step 1 — Choose a permanent storage location

Recommended (outside the repo):

```text
~/.mitoosa/upload-keystore.jks
```

Create the directory:

```bash
mkdir -p ~/.mitoosa
chmod 700 ~/.mitoosa
```

**Do not** place the keystore under `android/` in the git tree unless you are certain it is gitignored (`*.jks` is ignored).

---

## Step 2 — Generate the keystore with `keytool`

Run interactively (you will be prompted for passwords and distinguished-name fields):

```bash
keytool -genkey -v \
  -keystore ~/.mitoosa/upload-keystore.jks \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -alias upload
```

Suggested answers when prompted:

| Prompt | Suggestion |
|--------|------------|
| Keystore password | Strong unique password → save in password manager |
| Re-enter password | Same |
| Key password for `<upload>` | Press Enter to use same as keystore (typical for CI) |
| First and last name | Your org or app name, e.g. `miToosa` |
| Organizational unit | `Engineering` or leave default |
| Organization | `Chicademy` or your legal entity |
| City / State / Country | Your real jurisdiction (two-letter country code) |

**Check:**

```bash
keytool -list -v -keystore ~/.mitoosa/upload-keystore.jks -alias upload
```

You should see **Certificate fingerprints** including **SHA256**. Copy the SHA-256 line somewhere safe—you need it for task **5.3**.

---

## Step 3 — Back up the keystore

1. Copy `~/.mitoosa/upload-keystore.jks` to encrypted backup (password manager attachment, encrypted USB, or secure cloud vault).
2. Store all four secrets: file path, store password, alias `upload`, key password.
3. Confirm the file is **not** tracked:

```bash
cd /path/to/mitoosa
git check-ignore -v ~/.mitoosa/upload-keystore.jks || echo "OK if outside repo"
git status   # must not list any .jks or key.properties
```

---

## Step 4 — Create `android/key.properties`

From repo root:

```bash
cp android/key.properties.template android/key.properties
```

Edit `android/key.properties` (paths below assume repo root is current directory for Gradle; use an **absolute** `storeFile` to avoid path confusion):

```properties
storeFile=/home/YOUR_USER/.mitoosa/upload-keystore.jks
storePassword=YOUR_STORE_PASSWORD
keyAlias=upload
keyPassword=YOUR_KEY_PASSWORD
```

Replace `YOUR_USER` and passwords with your real values.

**Check:** File is ignored by git:

```bash
git check-ignore -q android/key.properties && echo "ignored OK"
```

---

## Step 5 — Build a signed release App Bundle

From repo root:

```bash
flutter pub get
flutter build appbundle --release
```

**Pass:**

- Build finishes without `GradleException` / `Missing: storeFile`.
- Artifact exists: `build/app/outputs/bundle/release/app-release.aab`.

**Fail:**

- Read the error’s `Missing:` field list; fix `android/key.properties`.
- See [docs/RELEASE-SIGNING.md](../RELEASE-SIGNING.md) → Troubleshooting → Android.

---

## Step 6 — Verify signature on the AAB

With Android SDK build-tools on `PATH`:

```bash
apksigner verify --print-certs build/app/outputs/bundle/release/app-release.aab
```

**Pass:** Command exits 0 and prints certificate DN and **SHA-256** fingerprint.

Save that SHA-256 for task **5.3**—it must match what you register in Play Console.

---

## Step 7 — Record completion

- [ ] `~/.mitoosa/upload-keystore.jks` created and backed up.
- [ ] `android/key.properties` populated locally (not committed).
- [ ] `flutter build appbundle --release` succeeds.
- [ ] `apksigner verify --print-certs` shows expected SHA-256.

Mark task **5.1** complete. Next: **5.3** (Play Console) or **5.2** (Apple) in parallel.
