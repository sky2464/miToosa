# Task 5.3 — Register upload-key SHA-256 in Play Console

**Story:** BL-01+02 · **Task:** 5.3 · **Deferred since:** 2026-05-16  
**Requirements:** AC-005, AC-010  
**Depends on:** Task **5.1** (upload keystore + SHA-256 from `keytool` or `apksigner`)

---

## Goal

Create the Play Console app (if needed), enable **Play App Signing**, and register your **upload key certificate** so release `.aab` uploads signed with `~/.mitoosa/upload-keystore.jks` are accepted.

---

## Before you start

- [ ] Task **5.1** complete: keystore exists; you have SHA-256 fingerprint.
- [ ] Google Play Console developer account with permission to create apps and manage **App integrity**.
- [ ] Application ID: `com.chicademy.mitoosa`.

### Get SHA-256 (if you do not have it saved)

```bash
keytool -list -v \
  -keystore ~/.mitoosa/upload-keystore.jks \
  -alias upload
```

Copy the **SHA256:** line (colon-separated hex).  
Or from a built AAB:

```bash
apksigner verify --print-certs build/app/outputs/bundle/release/app-release.aab
```

---

## Step 1 — Create the app in Play Console

1. Go to [Google Play Console](https://play.google.com/console).
2. **All apps** → **Create app**.
3. **App name:** miToosa (or store listing name).
4. **Default language**, **App or game** → **Game** (or **App** per your listing).
5. Declare policy declarations (ads, target audience, etc.) as required by Google.
6. **Create app**.

**Check:** Dashboard opens for your new app; package name will be set on first upload or under **App integrity** / setup flows.

---

## Step 2 — Complete initial setup checklist (high level)

Play Console shows a **Dashboard** checklist. For internal testing you typically need:

- [ ] **App access** declarations (if applicable).
- [ ] **Privacy policy** URL (required for production; may be needed before promoting tracks—add early).
- [ ] **Store listing** stub (short description, graphics) before promoting beyond internal test in some cases.

Exact requirements change; follow in-console prompts. Internal testing track is the lightest path (see **5.4**).

---

## Step 3 — Enable Play App Signing

1. In your app → **Setup** (or **Release**) → **App integrity** (formerly “App signing”).
2. Confirm **Play App Signing** is **on** (default for new apps created after 2021).

Google holds the **app signing key** used for devices; you only upload with the **upload key** from task **5.1**.

---

## Step 4 — Register your upload key certificate

Flow varies slightly by whether the app has **never** received a bundle:

### First upload (most common for miToosa)

1. Build signed AAB per **5.1**:

```bash
flutter build appbundle --release
```

2. **Release** → **Testing** → **Internal testing** (or **Production** → first create a release) → **Create new release**.
3. **Upload** `build/app/outputs/bundle/release/app-release.aab`.
4. On first upload, Play Console often **registers your upload key automatically** from the certificate embedded in the AAB.

If prompted to **opt in to Play App Signing** and choose upload key, accept defaults using the certificate from your first signed upload.

### Manual registration (if Console asks for upload certificate)

1. **App integrity** → **Upload key certificate** section.
2. **Add upload key** / **Request upload key reset** (only if support-guided).
3. Paste or upload certificate:
   - Export PEM from keystore:

```bash
keytool -export -rfc \
  -alias upload \
  -file ~/.mitoosa/upload-cert.pem \
  -keystore ~/.mitoosa/upload-keystore.jks
```

4. Upload `upload-cert.pem` where Play Console requests it.

---

## Step 5 — Verify fingerprint match (AC-010)

1. **App integrity** → note **Upload key certificate** → **SHA-256 certificate fingerprint**.
2. Compare to local:

```bash
keytool -list -v -keystore ~/.mitoosa/upload-keystore.jks -alias upload | grep SHA256
```

**Pass:** Play Console upload key SHA-256 equals your local upload keystore SHA-256 (ignore colon vs space formatting).

3. After a successful upload, open **Release** → **App bundle explorer** → select version → confirm **Signed with** upload certificate matches.

---

## Step 6 — Wrong-key prevention

| Symptom | Cause | Fix |
|---------|--------|-----|
| “signed with the wrong key” | Different keystore than registered | Restore original `upload-keystore.jks` from backup |
| Fingerprint mismatch | Typo or wrong alias | Re-list keystore; re-export cert |
| Lost keystore | No backup | Play Console → Help → **Upload key reset** (slow; avoid) |
