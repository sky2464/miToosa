# Part 1 — Android: Play Internal testing

## Step A1 — Build release bundle

```bash
cd /path/to/mitoosa
flutter pub get
flutter build appbundle --release
```

Artifact:

```text
build/app/outputs/bundle/release/app-release.aab
```

## Step A2 — Verify signature locally

```bash
apksigner verify --print-certs build/app/outputs/bundle/release/app-release.aab
```

Confirm SHA-256 matches Play Console **App integrity** upload key (task **5.3**).

## Step A3 — Create internal testing release

1. [Play Console](https://play.google.com/console) → your app → **Release** → **Testing** → **Internal testing**.
2. **Create new release** (or **Edit release**).
3. **Upload** `app-release.aab`.
4. **Release name** (e.g. `1.0.0 (1)` — match `versionName` / `versionCode` from `pubspec.yaml` if helpful).
5. **Release notes** (short; internal testers only).
6. **Review release** → **Start rollout to Internal testing**.

Wait for processing (minutes to hours). Status should reach **Available to internal testers**.

## Step A4 — Add internal testers

1. **Internal testing** → **Testers** tab.
2. Create an **email list** with Google accounts used on test devices.
3. Copy the **opt-in link** and open it on the Android device (logged into same Google account).

## Step A5 — Install on device

1. On device, accept invitation → **Download** from Play Store (internal test track).
2. Install **miToosa**.
3. Launch app (cold start): splash → main UI loads without immediate crash.

**Pass (T-007):** Install from Internal testing completes; app opens and is usable for a smoke session (start a level, navigate home).

**Fail:** See [RELEASE-SIGNING.md](../RELEASE-SIGNING.md) → wrong signing key, or Play processing errors in Console **Release** details.

# Part 2 — iOS: TestFlight

## Step I1 — Archive in Xcode

1. `open ios/Runner.xcworkspace`
2. Scheme **Runner** · destination **Any iOS Device (arm64)**.
3. **Product → Archive** (wait for completion).

## Step I2 — Validate (optional but recommended)

1. **Window → Organizer** → select the new archive.
2. **Validate App** → **App Store Connect** → defaults → **Validate**.

Fix any errors before uploading (missing compliance, icons, entitlements).

## Step I3 — Upload to App Store Connect

1. In Organizer → **Distribute App**.
2. **App Store Connect** → **Upload**.
3. Options: include bitcode/symbols per Xcode defaults (usually upload symbols yes).
4. Select signing: **Automatically manage signing** (Distribution cert from **5.2**).
5. **Upload** → wait for success dialog.

## Step I4 — Wait for processing

1. [App Store Connect](https://appstoreconnect.apple.com) → **Apps** → miToosa → **TestFlight**.
2. Build appears under **iOS Builds** with status **Processing** (~15–30 minutes typical).
3. When **Ready to Test**, proceed. If **Missing Compliance**, answer encryption questions (most Flutter apps: no custom encryption → exempt).

## Step I5 — Internal testing group

1. **TestFlight** → **Internal Testing** (App Store Connect users on your team).
2. **+** group or use default **App Store Connect Users**.
3. Add the build to the group.
4. Testers receive email or see build in **TestFlight** iOS app.

## Step I6 — Install on iPhone/iPad

1. Install **TestFlight** from App Store on device.
2. Accept invite / open miToosa in TestFlight → **Install**.
3. Launch miToosa (cold start).

**Pass (T-008):** Build status **Ready to Test**; device install via TestFlight succeeds; app launches.

**Fail:** **Invalid Binary** — read email from Apple; common fixes in [RELEASE-SIGNING.md](../RELEASE-SIGNING.md) (usage strings, Release vs Debug archive).
