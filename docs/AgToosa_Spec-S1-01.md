## Context

No staging deployment exists. `docs/RELEASE-GATES.md` has `Staging URL: TBD`. CI (`web-build.yml`)
produces a `build/web/` artifact on every push but deploys nowhere. Two project docs
(`docs/backend-research.md`, `docs/LAUNCH.md`) both recommend Firebase Hosting.

Firebase project creation is a **manual prerequisite** (requires human action in Firebase Console).
This spec covers all code and config that can be done immediately, plus step-by-step instructions
for the manual Firebase step.

### CI Deploy Step Design

```yaml
- name: Deploy to Firebase Staging
  if: github.ref == 'refs/heads/main' && env.FIREBASE_TOKEN != ''
  env:
    FIREBASE_TOKEN: ${{ secrets.FIREBASE_TOKEN }}
  run: |
    npm install -g firebase-tools
    firebase deploy --only hosting:mitoosa-staging --token "$FIREBASE_TOKEN"
```

The step is conditional on `FIREBASE_TOKEN` being set — the workflow passes today without it and
auto-deploys once the secret is added after Firebase project setup.

### scripts/deploy-staging.sh Design

```bash
#!/usr/bin/env bash
set -euo pipefail
flutter build web --no-tree-shake-icons --release
firebase deploy --only hosting:mitoosa-staging
```

## STRIDE Threat Model

| Threat | Category | Mitigation |
|--------|----------|------------|
| `FIREBASE_TOKEN` exposed in CI logs | Information Disclosure | Store as GitHub secret (masked); never echo |
| Staging URL publicly accessible (no auth gate) | Information Disclosure | Acceptable for Sprint 1 playtest; add IP restrict pre-production launch |
| Deploying unreviewed code to staging | Tampering | Deploy step triggers only on `main` branch (post-PR-merge) |
| Malicious third-party action compromise | Spoofing | Pin action versions with commit SHAs before production CI hardening |

## Manual Firebase Setup (step-by-step)

_See `docs/STAGING-SETUP.md` generated by this spec. Full steps:_

1. Go to [console.firebase.google.com](https://console.firebase.google.com) → Create project `mitoosa`
2. Enable Google Analytics in the project (needed for S1-02)
3. Install Firebase CLI: `npm install -g firebase-tools`
4. Login: `firebase login`
5. In repo root: `firebase init hosting`
   - Select project: `mitoosa`
   - Public directory: `build/web`
   - Configure as single-page app: `Yes`
   - Set up automatic builds with GitHub: `No` (CI handles this)
6. Generate CI token: `firebase login:ci` → copy token
7. Add `FIREBASE_TOKEN` to GitHub repo → Settings → Secrets → Actions
8. Update `docs/RELEASE-GATES.md` `Staging URL` with the assigned `*.web.app` or `*.firebaseapp.com` URL
